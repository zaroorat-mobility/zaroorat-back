# Quickstart & Validation Guide: Razorpay Driver Payments

**Feature**: `005-razorpay-driver-payments` | **Date**: 2026-10-19 | **Revised**: 2026-10-19 (second review: test matrix TM-01…TM-38, S3b, S4 defined, D8, corrected commands and links; third review: flag defaults, S11–S13, D10, wave-S split of TM-15/TM-23, wallet-mismatch alert; fourth review: TM-39, tighter TM-04/06/08/17/22/26/29/31). **Nothing in this guide has been run yet**; results go to the research.md verification log

This guide proves the feature works end to end and lists the evidence each production gate needs. Contracts: [contracts/http-api.md](./contracts/http-api.md), [contracts/razorpay-provider.md](./contracts/razorpay-provider.md). Data rules: [data-model.md](./data-model.md). Gates: [plan.md → Production gates](./plan.md#production-gates).

**Safety rules for every step**:

- Use test keys only, never live keys, until rollout step 3.
- Never trigger real SMS logins (dev login sends a real SMS).
- Run integration tests only against an isolated database, never the shared `zaroorat_test` while others use it.
- Never paste secrets, signatures, VPAs, card data, emails or phone numbers into evidence.


## Production rollout (task T105)

1. Deploy the migration (after the DATA checks), then the backend. Confirm the flags are at their seeded defaults: `payments.driver_checkout` OFF, `payments.subscription_checkout` OFF, `payments.pilot_mode` ON, allowlist empty.
2. Configure the live Razorpay webhook, live keys and the live webhook secret, with the alert email set to on-call and auto-capture at 3 days. Verify a signed test delivery.
3. Record the go decision in plan.md's sign-off record. Add the staff driver accounts to the allowlist and turn `payments.driver_checkout` on.
4. A staff driver makes a ₹1 live recharge using **UPI intent**, then Finance refunds it. Verify the ledger, wallet and Razorpay dashboard agree to the paisa.
5. Confirm every pilot driver (UD-4) is on the checkout build, then add them to the allowlist for the agreed period. Finance reviews payments, review cases and refunds daily. `payments.subscription_checkout` stays OFF.
6. Expand (turn `payments.pilot_mode` off) only when G8's expansion criteria hold.

Rollback: turn `payments.driver_checkout` off. No data rollback is needed: the migration is additive and existing intents still confirm.
